For someone whose promo deck has one lift number

The Flattering Baseline

The same weekends can read up against the weeks before and flat against last year. The comparison was chosen. You already have the register export.

This page stores nothing and does not log into a vendor. The command runs on your computer, on a file you already exported.

One claimed lift, four numbers

These dollars are invented, so the shape is visible. They are not a store. Three Friday–Sunday weekends, one store on the promo and one store that was not. The command prints:

  • Prior period, +7.0%. Promo days $8,560.00 a day. The same weekdays in the three weeks before, $8,000.00 a day. Cannot rule out: no seasonality control. A soft stretch before the promo makes an ordinary week look like a lift.
  • Year earlier, 0.0%. Those same October dates a year earlier were also $8,560.00 a day. Cannot rule out: no chain control. The whole street may have moved, and these calendar dates can fall on different weekdays.
  • Other stores, 0.0%. The store that did not run the promo was also $8,560.00 a day on those dates. Cannot rule out: this assumes the other stores are comparable. They can differ in size, hours, or neighborhood.
  • Weekdays, +22.3%. Monday–Thursday of the promo weeks were $7,000.00 a day. Cannot rule out: this only isolates a weekend-versus-weekday shift. Weekends differ from weekdays for reasons that have nothing to do with the promo.

The weekends before the promo were themselves −20.0% against those dates a year earlier ($8,000.00 a day against $10,000.00). That is why +7% can be the soft baseline, not the promo. The spread is the result. None of the four is the number to put back in the deck.

Run it on your export

Use a file you already have. Each row needs a date and the amount the customer paid. A store column is needed when more than one store is in the file. A customer column is ignored. Sums are taken for you, so one row per sale and one row per day both work.

python3 baseline.py illustrative.csv \
  --promo 2026-10-09:2026-10-11 \
  --promo 2026-10-16:2026-10-18 \
  --promo 2026-10-23:2026-10-25 \
  --stores main

illustrative.csv is the invented file above, in example/illustrative.csv. For your own file, name the stores that ran the promo. If you do not, and the file has more than one store, the command stops rather than mixing them.

What the four rows are

  • Prior period. The same weekdays, for the same number of weeks, immediately before the first promo week.
  • Year earlier. Those calendar dates one year earlier. 29 February becomes 28 February.
  • Other stores. The same promo dates, at stores you did not name. If the file has only your stores, the row says not in this file.
  • Weekdays. Monday–Thursday of the promo weeks, at your stores. If a promo date is itself Monday–Thursday, that row says not separate.

Per day uses dates that appear in the file. A missing date is not treated as zero. A closed day counts only if you include it with amount 0. A baseline that is zero or negative is baseline is not positive, not a percent.

What you can already do

A spreadsheet can divide any two totals you choose. The report that came with the promo usually asks you to pick one comparison. Neither of those puts these four numbers on one page and says what each one leaves open. This does only that.

What this does not do

  • It does not say the promo caused the change.
  • It does not log into a vendor, and it does not send your file anywhere.
  • It does not choose which number you should repeat.
  • It is not a monitor. Run it when a deck arrives. Nothing here runs after that.
  • The dollars on this page are invented. Point the command at your own export.
